7.1 scripts/r21_train_one.py 在首次空跑时报 KeyError('A_arm'),
    原因为 TEMPLATE_ROOT 字典键名与 condition 取值不一致。
    修正内容: TEMPLATE_ROOT 的键由 {"A","XML","DIR"} 改为 {"A_arm","XML","DIR"},
    template_path() 继续按 condition 取键。
    该修正发生在正式队列启动之前(空跑阶段),空跑最终结果 9/9 PASS。

7.2 scripts/r21_chain.sh 第6步影响面记录的排除模式有误(队列结束后发现并修正)。
    原实现(队列实际运行的版本):
        D=$ROOT/round21_v8data_20261009          # 绝对路径
        find . -newermt "$START" -type f -not -path "./$D/*" -not -path './.git/*'
    任务书第6步的 $D 是**相对**目录名(round21_v8data_20261009),
    故正确模式应为 "./<basename>/*"。使用绝对路径时该模式永不匹配,
    本轮目录自身的全部文件被算进影响面,交付物失去"本轮未改动既有文件"的证明力。
    实测:
        修正前 impact_project.txt            = 886 行,其中本轮目录自身 886 行(占 100%)
        修正前 impact_project_followlinks.txt = 887 行,其中本轮目录自身 887 行
    修正内容:
        DB=$(basename "$D")
        find . -newermt "$START" -type f -not -path "./$DB/*" -not -path './.git/*' > "$D/impact_project.txt"
        find -L . -newermt "$START" -type f -not -path "./$DB/*" -not -path './.git/*' > "$D/impact_project_followlinks.txt"
    修正后(START 与 END.txt 均未改动,仍为 2026-10-09 09:47:04 / 15:30:57):
        impact_project.txt             = 1 行  ->  ./round21_v8data.tar.gz
        impact_project_followlinks.txt = 1 行  ->  ./round21_v8data.tar.gz
        impact_settings_diff.txt       = 0 字节(settings.json 无差异)
        impact_ultralytics.txt         = 5 行(persistent_cache.json / settings.json 被触碰)
    即本轮除新建 round21_v8data_20261009/ 目录与 round21_v8data.tar.gz 外,
    未新建或修改项目内任何其它文件。
    数据集 cache 核查: exp_apspc_dose_20260817 与 exp_gc10_label_20260914 下的
    labels.cache / train.cache / val.cache 的 mtime 分别为 2026-08-16 与 2026-09-14,
    均早于 START;find -newermt START 命中数 = 0,即本轮复用了既有 cache 未重写,
    这解释了 followlinks 版与普通版结果一致(无额外文件)。
    处理: 4 个 impact_*.txt 已按修正后的命令重生成;
          launch_method_source.txt 已重生成,其 J 段为修正后的 r21_chain.sh 原文,
          并在文件头注明"与队列实际运行时略有差异";
          随后重新打包 round21_v8data.tar.gz。

7.3 scripts/r21_package.sh 的"每个 run 的 args.yaml 与 results.csv"清单有误。
    原实现:
        r=$(basename "$(dirname "$line")")      # line 取自 templates.txt
    而 templates.txt 记录的是**模板**路径(位于 exp_apspc_dose_unified_20260915/
    与 exp_gc10_label_20260914/ 下),其目录名是模板 run 名(含 yolo11n),
    与本轮目录内的 run 名(含 yolov8n)不同,导致 [ -f "$r/args.yaml" ] 恒为假,
    9 个 run 的 args.yaml / results.csv 会被静默漏掉(实测 0/9 命中)。
    修正内容: 增加名称映射,与 name_mapping.txt 规则一致
        t=$(basename "$(dirname "$line")")
        r=$(echo "$t" | sed 's/yolo11n/yolov8n/')
    沙箱复核: 修复前 tar 内 run 的 args.yaml=0 / results.csv=0;
              修复后 =9 / =9,且 logs/、*.pt、*.png、runs_eval/、weights/ 等
              不打包内容仍为 0 条。修复时队列尚未执行到打包步骤。
